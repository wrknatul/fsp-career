# ФСП.Карьера

Платформа подбора ИТ-специалистов с обратной механикой. Прототип для хакатона
«Лидеры цифровой трансформации» 2026, спецтрек Федерации спортивного
программирования. Команда «Граф магистралей».

**Посмотреть сразу:** [демо-страница с видео сценария](https://wrknatul.github.io/fsp-career/)
· [видео, 2,5 минуты](docs/demo/fsp-career-demo.mp4)
· [презентация, 12 слайдов](docs/presentation/fsp-career.pdf)
· [архитектура](docs/ARCHITECTURE.md)
· [интеграция с ФСП](docs/FSP_INTEGRATION.md)
· [контракт API](docs/API_CONTRACT.md).
Прототип поднимается одной командой — см. «Запуск одной командой» ниже.

## Что это

**Задача.** Организатор просит самостоятельную платформу, которая напрямую
связывает работодателя и соискателя: без парсинга чужих сайтов и без витрины
чужих вакансий. Нужно формализовать отраслевую специфику — стек, грейд, роль
в команде, формат работы. Доступа к данным реестра ФСП у нас нет, поэтому
реестр в прототипе смоделирован, а формат обмена с ним мы предлагаем сами
(см. [docs/FSP_INTEGRATION.md](docs/FSP_INTEGRATION.md)).

**Обратная механика.** Соискатель ни на что не откликается. Он собирает
профиль, а платформа сама относит его к категории: стек, грейд, роль в
команде, формат работы. Работодатель выбирает нужную категорию («Backend ·
Middle · удалённо»), смотрит кандидатов с объяснением, почему они подходят, и
сам отправляет оффер с суммой зарплаты. Вакансии заводит только работодатель.
Кнопки «откликнуться» в продукте нет.

**Чем подтверждается профиль.** У каждого факта есть источник и уровень
подтверждения: результаты в реестре ФСП, экспресс-тест на платформе, резюме
(разбирается правилами) или слова самого соискателя. Подтверждённое весит
больше заявленного, а неподтверждённое помечено как неподтверждённое.
Грейд раскрывается до слагаемых: видно, сколько баллов дали опыт, тесты и
результаты ФСП. Персональные данные не покидают платформу: внешних вызовов нет,
а до принятого оффера работодатель видит только «Алексей С.» без контактов.

## Запуск одной командой

Нужны Docker и плагин Docker Compose. Файл `.env` не обязателен.

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. База, API и веб стартуют по цепочке:
веб поднимается, когда API здоров, а API — когда готова база. Поэтому первые
минуты страница может не открываться. На пустой базе приложение само создаёт
демо-данные.

| Что | Адрес |
| --- | --- |
| Веб-интерфейс | http://localhost:8088 |
| API | http://localhost:8100/api/v1/health |
| Документация API (Swagger) | http://localhost:8100/api/docs, то же через веб: http://localhost:8088/api/docs |
| PostgreSQL | `localhost:5544`, пользователь `fsp`, пароль `fsp_dev_password`, база `fsp_career` |

Порты 5432 и 8000 мы намеренно не занимаем: на машинах разработчиков они
часто заняты. Если занят один из наших, поменяйте `WEB_PORT`, `API_PORT` или
`DB_PORT` в `.env` (шаблон — `.env.example`).

Демо-учётки. Пароль у всех: `demo12345`.

| Почта | Кто |
| --- | --- |
| `demo.candidate@fsp-career.test` | соискатель «Смирнов Алексей Игоревич» |
| `demo.employer@fsp-career.test` | работодатель «Северный код» |
| `hr@orbita-soft.test` | работодатель «Орбита Софт» |
| `hr@neurolab.test` | работодатель «Нейролаб» |

На главной странице есть две кнопки быстрого входа в демо.

Короткие команды (`make` без аргументов покажет список):

```bash
make up          # то же, что docker compose up --build -d
make logs        # логи всех сервисов
make down        # остановить; данные базы сохраняются в томе
make seed-reset  # вернуть демо-данные в исходное состояние
```

## Сценарий показа на 5 минут

Перед показом выполните `make seed-reset`: сценарий рассчитан на исходное
состояние демо-соискателя (ФСП не привязан, резюме нет, тестов нет, во входящих
один оффер). Если на показе что-то пошло не так, тот же `make seed-reset`
возвращает всё назад за секунды, не дожидаясь паузы между тестами.

1. **Вход соискателем** (≈ 0:20). `demo.candidate@fsp-career.test`. Категория
   «не определена», во входящих один оффер от «Орбиты Софт». Мысль: профиля
   нет, а предложение уже пришло — работодатель ищет сам.
2. **Привязка ФСП ID** (≈ 0:40). Раздел «ФСП», номер `FSP-2024-00117`.
   Подтянулись 6 результатов и разряд КМС; факты помечены «Подтверждено ФСП».
   Категория стала `Backend · Junior` с пояснением «без опыта работы грейд не
   выше Junior». Мысль: платформа не верит на слово, и объясняет, чего не
   хватает.
3. **Резюме** (≈ 0:40). Кнопка «подставить пример резюме», затем разбор: навыки,
   1,5 года опыта, формат работы; факты помечены «Из резюме». Грейд стал
   `Middle`.
4. **Экспресс-тест по Python** (≈ 0:40). 6 вопросов на понимание, лимит 8 минут.
   Навык получает метку «Подтверждено тестом», опыт из резюме засчитывается с
   большим доверием, баллы растут. Тест не сдан — не беда: повторить можно через
   10 минут после начала прошлой попытки (в Docker `TEST_COOLDOWN_MINUTES=10`)
   или сразу после `make seed-reset`.
5. **Олимпиада вручную** (≈ 0:20). Достижение попадает в профиль как «Заявлено»,
   его вклад в грейд — только 35%. Мысль: своё слово весит меньше протокола.
6. **Вход работодателем** (≈ 0:30). `demo.employer@fsp-career.test`, компания
   «Северный код». Матрица «стек × грейд»: сколько кандидатов в каждой клетке.
7. **Поиск** (≈ 0:50). Фильтры плюс текст запроса. В выдаче оценка 0–100 и
   раскрываемое «почему». Переключатель «только с результатами ФСП» оставляет
   не меньше 5 кандидатов.
8. **Оффер** (≈ 0:30). Открыть карточку демо-соискателя («Алексей С.», контактов
   нет) и отправить оффер с зарплатой по вакансии «Python-разработчик».
9. **Принятие** (≈ 0:30). Снова войти соискателем: во входящих два оффера, берём
   новый, от «Северного кода», и жмём «Принять». Теперь стороны видят контакты
   друг друга, а работодатель — полное ФИО (проверить, снова войдя
   работодателем).

## Развёртывание на сервере

На публичном стенде должны быть **только тестовые данные**. Все люди,
компании и протоколы в демо вымышлены, пароли демо-учёток публичны, регистрация
открыта всем. Не вносите на стенд настоящие персональные данные, свои или
чужие.

**1. Что нужно.** Linux-сервер, Docker Engine и плагин Docker Compose (команда
`docker compose`), домен, направленный на сервер, открытые порты 80 и 443.

**2. Код и переменные.**

```bash
git clone <адрес репозитория> fsp-career && cd fsp-career
cp .env.example .env
```

В `.env` обязательно замените:

- `JWT_SECRET` — длинная случайная строка: `openssl rand -hex 32`. С
  заводским значением любой может выписать себе токен любого пользователя.
  Смена значения разлогинит всех.
- `POSTGRES_PASSWORD` — только буквы и цифры (пароль попадает в адрес базы).
  Пароль применяется один раз, при создании тома с базой; позже его в `.env`
  уже не поменять.
- `WEB_BIND=127.0.0.1` и `API_BIND=127.0.0.1` — веб и API слушают только
  localhost, наружу их отдаёт обратный прокси. База по умолчанию уже привязана
  к localhost.
- `TEST_COOLDOWN_MINUTES=1440` — для публичного стенда пауза между тестами в
  сутки; для живого показа оставьте 10.

**3. Запуск.**

```bash
docker compose up --build -d
docker compose ps
curl -s http://127.0.0.1:8100/api/v1/health
```

**4. Обратный прокси с TLS.** Пример для Caddy: сертификат он выпускает и
продлевает сам. В `/etc/caddy/Caddyfile`:

```
fsp.example.com {
    reverse_proxy 127.0.0.1:8088
}
```

После `sudo systemctl reload caddy` сайт открывается по `https://fsp.example.com`.
Один прокси на веб-порт достаточно: контейнер `web` сам отдаёт `/api/*` в API,
в том числе `/api/docs`.

**5. Сброс демо-данных.** Вернуть базу к исходным демо-данным:

```bash
docker compose exec backend python -m app.seed --reset
```

Всё, что пользователи завели на стенде (регистрации, вакансии, офферы), при
этом удаляется. Полностью стереть базу вместе с томом: `docker compose down -v`.

**6. Обновление версии.**

```bash
git pull
docker compose up --build -d
```

Миграции применяются автоматически при старте API, данные в томе остаются.
Перед обновлением полезно сделать копию базы:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

## Локальная разработка без Docker

Нужны Python 3.12 и Node.js 22.

**Бэкенд** (порт 8100, по умолчанию SQLite-файл `backend/dev.sqlite3`):

```bash
cd backend
python3.12 -m venv .venv                       # или: make venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head                 # схема базы
.venv/bin/uvicorn app.main:app --reload --port 8100
```

На пустой базе демо-данные создаются при старте (`SEED_DEMO_DATA` по умолчанию
включён). Пересоздать их: `.venv/bin/python -m app.seed --reset`.

Настройки бэкенд берёт из переменных окружения и из файла `backend/.env`, если
он есть (корневой `.env` читает только Docker Compose).

Чтобы работать на PostgreSQL, поднимите только базу командой
`docker compose up -d db` и запустите бэкенд с
`DATABASE_URL=postgresql+psycopg://fsp:fsp_dev_password@localhost:5544/fsp_career`.

**Фронтенд** (порт 5173; запросы на `/api` проксируются на 8100):

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Фронтенд ходит только на `/api/*`, шрифты
поставляются вместе со сборкой, внешних CDN нет.

## Тесты и проверки

```bash
make test         # pytest в backend/.venv
make lint         # ruff
make typecheck    # vue-tsc во frontend
make build-web    # проверка типов и сборка фронтенда
```

Автотесты бэкенда идут на SQLite в памяти: быстро и без внешних сервисов.
Отдельный тест прогоняет миграции Alembic на временном SQLite-файле и сверяет
схему с моделями. Работу на PostgreSQL 17 проверяет сам запуск
`docker compose up --build` и демо-сценарий из этого файла. Подробности — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Ограничения MVP

Мы стараемся не обещать лишнего. Вот что в прототипе устроено упрощённо:

- **Реестр ФСП смоделирован.** Доступа к настоящим данным и их формату у нас нет.
  Спортсмены, соревнования, места и протоколы вымышлены (ссылки ведут на
  `fsp.example`). В интерфейсе это написано.
- **Привязка по ФИО и дате рождения** вместо входа через аккаунт ФСП. Это
  самый слабый способ подтвердить личность. Рабочая версия — вход через аккаунт
  ФСП с согласием спортсмена (см. [docs/FSP_INTEGRATION.md](docs/FSP_INTEGRATION.md)).
  Число попыток ограничено: 5 в час.
- **Резюме разбирается правилами, без языковой модели.** Формат — `.txt`, `.pdf`
  до 2 МБ или вставленный текст. Нестандартная вёрстка и редкие формулировки
  могут разобраться неточно. `.docx`, образование и текст вакансий не
  разбираются: мы сознательно это не делали.
- **Текстовое сходство лексическое, а не семантика.** Совпадение с текстом
  запроса считается по словам и кускам слов (локальный вектор), а не по смыслу.
  Синонимы без общих слов оно не поймает.
- **Банк вопросов открыт вместе с кодом.** Экспресс-проверка из 6 вопросов —
  ориентир, а не аттестация. В рабочей версии банк хранится отдельно и
  ротируется. Тестов четыре: Python, JavaScript, SQL, алгоритмы.
- **У офферов нет срока действия.** Оффер висит, пока соискатель не ответит.
- **Работодатели не проходят проверку.** Метка «Компания проверена» стоит только
  у демо-компаний; все, кто зарегистрируется сам, помечены «Не проверена».
- **Баллы за разряды условные.** Их нужно уточнить с ФСП. Набор уровней
  соревнований — допущение команды, веса уровней и мест тоже наши. МСМК, ЗМС и
  юношеские разряды пока не учитываются.

## Структура репозитория

```
fsp-career/
├── docker-compose.yml        база + API + веб одной командой
├── .env.example              все переменные окружения с комментариями
├── Makefile                  короткие команды (make без аргументов)
├── README.md
├── docs/
│   ├── SPEC.md               спецификация MVP
│   ├── API_CONTRACT.md       контракт API v1
│   ├── ARCHITECTURE.md       техническая документация
│   └── FSP_INTEGRATION.md    предложение ФСП по интеграции
├── backend/                  FastAPI, SQLAlchemy 2.0, Alembic
│   ├── Dockerfile, entrypoint.sh
│   ├── requirements.txt, requirements-dev.txt
│   ├── alembic/              миграции
│   ├── app/
│   │   ├── main.py           создание приложения, маршруты /api/v1
│   │   ├── api/              маршруты и зависимости (роли, токен)
│   │   ├── core/             настройки, безопасность, ошибки, время
│   │   ├── db/, models/      подключение к базе, таблицы
│   │   ├── schemas/          pydantic-схемы контракта
│   │   ├── services/         сборка профиля, поиск
│   │   ├── domain/           чистая логика: онтология, резюме, тесты, грейд, матчинг
│   │   ├── fsp_registry/     смоделированный реестр ФСП и его данные
│   │   ├── seed.py           демо-данные (python -m app.seed [--reset])
│   │   └── seed_data/        тексты резюме для демо
│   └── tests/                pytest
└── frontend/                 Vue 3, Vite, Pinia, TypeScript
    ├── Dockerfile, nginx.conf
    └── src/                  страницы, компоненты, клиент API
```
